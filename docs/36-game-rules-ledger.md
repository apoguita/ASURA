# Game rules ledger

The owner's working rule (2026-11-02): **assume everything we know about how the game works is
wrong until the owner asserts otherwise.** This page tracks that assumption, so a rule carried in
from a document, a capture, a wiki, or memory is never read as fact merely because it is written
down.

**Phase assumption (owner, 2026-11-02): the game and Eden are the reference, and our own code is
assumed wrong.** "This task is about achieving parity on that; if Eden or the game tells you
something, you should listen; we are only assuming our own code is not correct for this phase."
Where our code and the game or Eden disagree, the game or Eden wins, and the disagreement is a code
fix to be scheduled, never a reason to edit the evidence.

## Status vocabulary

| status | meaning | what happens |
|---|---|---|
| **Asserted** | the owner stated it, with a date | the code must comply |
| **Evidenced** | a source witness states it (a decompiled message definition, a capture, the wiki) | treat as fact for the code; the witness is named |
| **Contradicted** | an assertion says the opposite of what a document, the code, or a prior row says | keep both rows; the assertion wins; add a compliance item |
| **Suspect** | carried in and not asserted or witnessed | code must not depend on it without raising it |
| **Unknown** | needed, nobody has established it | ask or measure; do not infer |

Rules are never deleted. A contradicted rule keeps its row and its contradicting row.

## How this ledger is used

1. **Before behaviour changes:** the implementation agent checks the affected rows here. Anything
   only *Suspect* is raised with the owner before it becomes load-bearing.
2. **When the owner gives a rule:** add or flip a row under *Asserted* with the date. If it
   contradicts existing text, add a *Contradicted* row and a compliance item; never silently edit
   the older document away.
3. **When code is written from an asserted row:** the compliance item names the crate/file and the
   row, so behaviour can be traced to the owner's words.
4. **Documents stay descriptive.** `docs/22-world-model.md`, `docs/32-world-simulation-plan.md` and
   `docs/30-world-content-and-scripting.md` carry the detail; this page carries the status. Where
   they disagree with a row here, the row here wins and the document is corrected to match.
